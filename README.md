## 1. 项目目标

做一个**可在浏览器里直接打开**的旅行规划小系统，帮助学生理解：

- 一个网页应用通常由哪些页面组成
- 用户填写的信息如何保存、刷新后还能看到
- 同一趟旅行里的「地点 / 待办 / 日历 / 攻略 / 地图」如何共用同一份数据

本项目是**课堂学习原型**，重点不是做成商业 App，而是让学生能看懂、能改、能演示。

---

## 2. 目标用户

| 用户 | 说明 |
|---|---|
| 课堂学生（零基础 / 初学前端） | 用来学习页面结构、交互和本地保存 |
| 授课教师 | 用来现场演示「创建旅行 → 加地点 → 看日历/攻略同步」 |
| 自学练习者 | 在本机打开文件，按验收标准自测功能是否跑通 |

不面向真实出行订票、不要求账号登录。

## 3. 核心功能

### 已实现（课堂主流程）

1. **创建 / 管理旅行**  
   填写名称、目的地、起止日期、封面等，在「我的旅行」中查看、编辑、进入某一趟旅行。

2. **旅行工作台**  
   进入某趟旅行后，可在多个子页之间切换：概览、攻略、地图、待办、日历（笔记与相册为预留位）。

3. **地图路线规划（Google Maps）**  
   - 底图使用 Google Maps JavaScript API（需配置 `GOOGLE_MAPS_API_KEY`）  
   - 按日期查看当天地点顺序  
   - 搜索地点（Google Places，失败时回退 Nominatim）、地图选点、加入某天路线  
   - 调整顺序、编辑地点信息  
   - **地图上的连线表示“计划访问顺序”，不是真实导航路线**  
   - 路程/时间仅为示意，**不代表真实交通方案**（未按公交、步行、驾车等真实路况计算）

4. **待办 Todo**  
   为当前旅行添加任务（标题、日期/旅行第几天、优先级、分类、备注），可完成、编辑、删除。

5. **日历**  
   按月查看；选中某一天后，展示**当天的地点 + 待办**。

6. **攻略（按日整理）**  
   按旅行每一天汇总同一天的地点与待办；可从攻略跳到地图或待办。

7. **数据联动**  
   在地图、待办、日历、攻略中，**同一天的事项应能互相看见**（改一处，其他页能看到对应内容）。

8. **中英文界面**  
   设置或顶栏可切换语言；界面文案切换，用户自己填写的内容不自动翻译。

9. **示例数据**  
   首次打开可带一趟示例旅行（如 Chiang Mai Trip），方便马上点进工作台体验，**不是实时旅行资讯**。

### 尚未完整实现（页面有入口，功能为占位）

- **笔记 Notes**：工作台有入口，当前为“即将到来”占位说明  
- **相册 Gallery**：同上  

首页/概览里可能仍能看到示例笔记、照片数量等预览信息，但不代表笔记/相册编辑功能已完成。

## 5. 数据保存方式

- 使用浏览器 **LocalStorage** 保存  
- 主要键名：`travelAppData`（一个对象里放旅行、地点、路线、待办、笔记、照片、语言、当前旅行等）  
- **刷新页面后数据还在**；换浏览器、清缓存、或换电脑则看不到原数据  
- **没有服务器、没有账号登录**；数据只存在本机浏览器里  
- 不适合存大量原图；课堂版以文字、链接、小预览为主

## 6. 本地运行方式

1. 用电脑打开文件夹：`第四节课/案例/06-旅行规划小系统/`  
2. 用浏览器打开 `index.html`（推荐 Chrome / Edge）  
3. 地图底图与搜索需要**联网**，并配置 `GOOGLE_MAPS_API_KEY` 后用 `npm start` 打开  
4. 未配置 Google Key 时，地图页会显示提示；地点搜索仍可能回退到 Nominatim  

基本页面可用浏览器直接打开；**Google 底图与 AI** 需要 `npm start` 并配置对应 Key。

## 7. 课堂版本限制

请明确告诉学生：**这是学习原型，不是完整出行产品。**

| 限制 | 说明 |
|---|---|
| 无后端 / 无登录 | 数据只在本机浏览器 |
| 交通方式未真实规划 | 不提供公交/地铁/驾车实时路线；连线只表示地点顺序；估算路程仅示意 |
| 不做目的地时效信息 | 不提供营业时间、门票余量、实时天气、航班延误等“会过期”的信息 |
| 地图连线 ≠ 导航 | 界面会提示：顺序连线，非实际导航 |
| 笔记 / 相册未完成 | 有入口与占位文案，完整编辑留到后续 |
| 搜索依赖网络 | 断网时地点搜索可能失败；需换关键词或地图点选 |
| 多端不同步 | 手机和电脑浏览器数据不自动同步 |
| 示例旅行仅演示 | 示例目的地与日期用于课堂体验，不代表真实行程推荐 |

关于交通：课堂版应让学生理解「规划里需要考虑怎么去」，但**本 MVP 只做到按日排地点顺序**；真实怎么坐车、要多久，需学生自行用地图 App 核对，不在本系统自动完成。

## 8. 课堂 MVP 实现验收标准

验收时建议按下面清单打勾（适合零基础对照操作）。

### A. 基础可用

- [ ] 能打开页面，看到首页 / 我的旅行 / 设置  
- [ ] 能创建一趟新旅行（名称、目的地、起止日期）并出现在「我的旅行」  
- [ ] 能进入该旅行的工作台，并在子页之间切换  

### B. 地图与地点

- [ ] 能在某天添加至少一个地点（搜索或地图选点）  
- [ ] 当天路线列表能看到该地点，地图上有对应标记  
- [ ] 能理解并看到提示：连线是顺序，不是真实导航  
- [ ] （可选）能调整顺序或编辑地点名称后列表更新  

### C. 待办

- [ ] 能为当前旅行新增一条待办并保存成功  
- [ ] 能勾选完成 / 再编辑或删除  
- [ ] 待办能关联到日期或「旅行第几天」  

### D. 联动（重点）

- [ ] 地图某天加了地点后，**攻略**对应日期能看到  
- [ ] 待办安排到某天后，**日历**当天能看到  
- [ ] 日历「当天行程」里，地点和待办能一起出现  
- [ ] 在攻略点击地点可跳到地图相关日期；点击待办可进入待办编辑  

### E. 本地保存与语言

- [ ] 刷新页面后，刚才创建的旅行 / 地点 / 待办仍在  
- [ ] 能切换中文 / English，按钮和标题等界面文案会变  

### F. 明确不验收（避免超纲）

- [ ] 不要求真实公交/驾车导航与准确 ETA  
- [ ] 不要求营业时间、票务、天气等时效数据  
- [ ] 不要求笔记、相册的完整增删改  
- [ ] 不要求多用户账号与云同步

## 附：给教师的一句话介绍

> 这是一个纯前端的旅行规划课堂原型：学生可以创建旅行，用地图按天排地点、用待办排任务，并在日历和攻略里看到同一天的安排；数据存在浏览器本地。它帮助理解页面与数据，不替代真实导航和出行查询。
